# План реализации skill для LiveLib wish-list

## Цель

Пользователь отправляет ссылку на обычную страницу списка книг LiveLib:

```text
https://www.livelib.ru/reader/LiraLantan/wish
```

Skill открывает публичную страницу LiveLib wish-list в браузерном режиме,
получает страницы wish-list с учетом пагинации, извлекает книги со всех страниц
и сохраняет список в JSON. Следующим этапом skill ищет найденные книги на
`https://books.yandex.ru/` и добавляет к каждой книге ссылки на найденные
страницы Яндекс Книг.

Минимальные поля для каждой книги:

```json
{
  "title": "Сто лет одиночества",
  "authors": ["Габриэль Гарсиа Маркес"],
  "url": "https://www.livelib.ru/book/...",
  "yandex_books_urls": [
    "https://books.yandex.ru/books/..."
  ]
}
```

## MVP

Сделать один skill `livelib-wishlist`, который умеет:

1. [x] Принимать URL вида `https://www.livelib.ru/reader/<username>/wish`.
2. [x] Открывать страницу в браузерном режиме `--browser`.
3. [x] Открывать публичную страницу wish-list без проверки авторизации.
4. [x] Использовать постоянный браузерный профиль для сохранения сессии.
5. [x] Находить ссылки пагинации и открывать все страницы wish-list.
6. [x] Находить книги в списке на каждой странице.
7. [x] Извлекать название, авторов и ссылку на книгу LiveLib.
8. [x] Сохранять результат в JSON-файл.
9. [x] Сообщать путь к файлу, количество найденных книг и количество обработанных страниц.

## Этап 2: ссылки на Яндекс Книги

После составления списка книг из LiveLib добавить обогащение через
`https://books.yandex.ru/`.

Skill должен уметь:

1. [x] Для каждой книги из результата LiveLib формировать поисковый запрос по названию и авторам.
2. [x] Открывать поиск Яндекс Книг в браузерном режиме.
3. [x] Находить ссылки на страницы книг на `books.yandex.ru`.
4. [x] Отбирать только результаты, похожие на исходную книгу по названию и авторам.
5. [x] Сохранять все подходящие ссылки в поле `yandex_books_urls`.
6. [ ] Если книга не найдена на Яндекс Книгах, сохранять пустой массив `yandex_books_urls: []`.
7. [ ] Ограничивать количество проверяемых результатов на книгу, например `--yandex-max-results 5`.
8. [ ] Делать задержку между поисковыми запросами, например `--yandex-delay-ms 1500`.
9. [ ] Не перезаписывать LiveLib-поля при обогащении.
10. [ ] Если выходной JSON уже существует, читать его и не искать заново книги, у которых `yandex_books_urls` уже заполнен.
11. [ ] Сообщать количество книг, для которых найдены ссылки Яндекс Книг, и количество книг, пропущенных из-за уже существующих ссылок.

## SKILL.md

В `SKILL.md` описать:

- когда использовать skill: если пользователь прислал ссылку на LiveLib wish-list page;
- какой скрипт запускать;
- какой формат входа и выхода ожидается;
- какие ограничения соблюдать.

Пример workflow для агента:

1. Проверить, что ссылка похожа на `/reader/<username>/wish`.
2. Запустить скрипт `scripts/livelib-wish-to-json.mjs` в режиме `--browser`.
3. Открыть публичную страницу wish-list без ожидания ручной авторизации.
4. После открытия wish-list обработать первую страницу и все страницы пагинации текущего wish-list.
5. При включенном обогащении найти книги на Яндекс Книгах и добавить ссылки в результат.
6. Сохранить JSON в указанное место или в файл по умолчанию.
7. Вернуть пользователю количество книг, количество страниц, количество найденных совпадений Яндекс Книг и путь к результату.

## CLI-скрипт

Интерфейс:

```bash
node scripts/livelib-wish-to-json.mjs \
  "https://www.livelib.ru/reader/LiraLantan/wish" \
  --browser \
  --out wishlist.json \
  --max-pages 50 \
  --with-yandex-books
```

Рекомендуемые зависимости:

- `playwright` для браузерного режима;
- `cheerio` для парсинга HTML.

Установка браузерной зависимости:

```bash
npm install
npx playwright install chromium
```

Прямой HTTP-загрузчик и режим `--html` можно оставить как fallback, но основной
пользовательский сценарий должен идти через `--browser`.

## Браузерный режим

Основной режим работы:

1. Запустить Chromium через Playwright в видимом режиме.
2. Использовать постоянный профиль, например `.browser-profile/`, чтобы сессия LiveLib сохранялась между запусками.
3. Открыть URL wish-list, который дал пользователь.
4. Не выполнять отдельную проверку авторизации: публичный wish-list должен открываться без входа.
5. Если LiveLib показывает защитную или промежуточную страницу, не обходить ее автоматически.
6. Не сохранять пароль, cookie или другие данные отдельно от браузерного профиля.

Параметры CLI:

- `--browser` - использовать браузерный режим;
- `--profile-dir .browser-profile` - путь к постоянному профилю браузера;
- `--headed` / видимый режим по умолчанию;
- `--max-pages 50` - лимит страниц пагинации.
- `--with-yandex-books` - после сбора LiveLib искать книги на Яндекс Книгах;
- `--yandex-max-results 5` - максимум результатов Яндекс Книг для проверки на одну книгу;
- `--yandex-delay-ms 1500` - задержка между запросами к Яндекс Книгам.

## Парсинг

Основная логика для каждой страницы:

1. Найти ссылки на книги LiveLib.
2. Оставить ссылки, которые ведут на `/book/...` или `/work/...`.
3. Взять текст ссылки как название книги.
4. Найти автора или авторов рядом с названием.
5. Преобразовать относительные ссылки в абсолютные URL `https://www.livelib.ru/...`.
6. Убрать дубли.
7. Сохранить список объектов в JSON.

## Пагинация

Список книг на обычной странице wish-list может быть разбит на несколько
страниц. Скрипт должен собрать книги со всех страниц текущего списка.

Подход:

1. Начать с URL, который дал пользователь.
2. После открытия страницы в браузере найти ссылки пагинации.
3. Оставить только ссылки того же пользователя и того же раздела `/reader/<username>/wish`.
4. Оставить только реальные ссылки пагинации, а не любые ссылки на `/wish`.
5. Игнорировать футерные, мобильные и трекинговые ссылки, например `utm_*` и `version=mobile`.
6. Нормализовать относительные ссылки в абсолютные URL.
7. Обработать страницы без повторов.
8. Остановиться, когда новых ссылок пагинации больше нет.
9. Использовать лимит безопасности, например `--max-pages 50`.

Скрипт не должен переходить в другие разделы профиля, книги, рецензии,
подборки или страницы других пользователей. Разрешены только URL текущего
wish-list и его пагинации.

Если браузерный режим недоступен, режим `--html` может обработать сохраненный
HTML-файл одной страницы. Это fallback, а не основной сценарий.

## JSON-схема

```json
[
  {
    "title": "string",
    "authors": ["string"],
    "url": "string",
    "yandex_books_urls": ["string"]
  }
]
```

Поле `authors` лучше хранить массивом, даже если автор один. Поле
`yandex_books_urls` хранит массив, потому что на Яндекс Книгах может быть
несколько подходящих страниц или изданий. Если совпадений нет, массив должен
быть пустым.

## Поиск на Яндекс Книгах

Основная логика обогащения:

1. Для каждой книги взять `title` и `authors`.
2. Построить поисковый запрос вида `<title> <authors>`.
3. Открыть поиск на `https://books.yandex.ru/`.
4. Извлечь ссылки на страницы книг в домене `books.yandex.ru`.
5. Сравнить текст результата с названием и авторами исходной книги.
6. Добавить все подходящие URL в `yandex_books_urls`.
7. Убрать дубли ссылок.
8. Если выходной JSON уже существует, перед поиском сопоставить текущие книги с сохраненными по LiveLib `url`.
9. Для книг, у которых в существующем JSON уже есть непустой `yandex_books_urls`, перенести эти ссылки в новый результат и пропустить поиск.
10. Для книг без `yandex_books_urls` или с пустым массивом выполнить поиск на Яндекс Книгах.
11. Если сайт показывает защитную или промежуточную страницу, остановиться без сохранения частичного результата.

Сопоставление должно быть осторожным: лучше не добавить сомнительную ссылку,
чем записать явно неправильную книгу. На первом этапе достаточно простого
эвристического сравнения нормализованных названий и авторов.

Повторный запуск обогащения должен быть инкрементальным: уже найденные ссылки
Яндекс Книг сохраняются, а сетевые запросы выполняются только для книг, у
которых ссылок еще нет.

## Тесты

Покрыть сценарии:

1. Одна книга.
2. Несколько книг.
3. Несколько авторов у одной книги.
4. Относительная ссылка `/book/...`.
5. Дубли ссылок.
6. Пагинация на две страницы.
7. Дубли страниц пагинации.
8. Ссылка пагинации в другой раздел игнорируется.
9. Футерная ссылка на `/wish` с `utm_*` игнорируется.
10. Ссылка на мобильную версию с `version=mobile` игнорируется.
11. Лимит `--max-pages`.
12. Браузерный режим открывает первую страницу и переходит только по реальной пагинации.
13. Публичная страница wish-list открывается без ожидания ручной авторизации.
14. Пустая страница.
15. Изменившаяся верстка, при которой книги не найдены.
16. Книга найдена на Яндекс Книгах.
17. Книга не найдена на Яндекс Книгах.
18. Несколько подходящих ссылок Яндекс Книг для одной книги.
19. Неподходящие результаты Яндекс Книг игнорируются.
20. Дубли ссылок Яндекс Книг удаляются.
21. Защитная или промежуточная страница Яндекс Книг останавливает обогащение без сохранения частичного результата.
22. Повторный запуск с существующим JSON пропускает книги с уже заполненным `yandex_books_urls`.
23. Повторный запуск ищет только книги, у которых `yandex_books_urls` отсутствует или пустой.

## Ограничения

Для аккуратной работы:

- открывать только страницу, которую дал пользователь, и страницы пагинации этого же wish-list;
- не автоматизировать логин;
- не обходить капчи и защитные механизмы;
- не сканировать другие разделы LiveLib;
- не считать футерные, мобильные и трекинговые ссылки частью пагинации;
- ограничивать количество страниц параметром `--max-pages`;
- ограничивать количество результатов и частоту запросов к Яндекс Книгам;
- хранить сессию только в локальном браузерном профиле `.browser-profile/`;
- не сохранять лишние данные, кроме названия, авторов, ссылки LiveLib и ссылок Яндекс Книг.

## Возможные следующие этапы

После MVP можно добавить:

- экспорт в Markdown или CSV;
- сравнение нового JSON со старым;
- отметку новых и удаленных книг;
- настройку имени выходного файла;
- поддержку нескольких сохраненных HTML-файлов для офлайн-сбора всех страниц;
- прямой HTTP-режим как технический fallback;
- более точное сопоставление книг через ISBN или внешние книжные API.
