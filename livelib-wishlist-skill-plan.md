# План реализации skill для LiveLib wish-list

## Цель

Пользователь отправляет ссылку на печатную версию списка книг LiveLib:

```text
https://www.livelib.ru/reader/LiraLantan/wish/print
```

Skill получает страницу, извлекает книги и сохраняет список в JSON.

Минимальные поля для каждой книги:

```json
{
  "title": "Сто лет одиночества",
  "authors": ["Габриэль Гарсиа Маркес"],
  "url": "https://www.livelib.ru/book/..."
}
```

## MVP

Сделать один skill `livelib-wishlist`, который умеет:

1. [x] Принимать URL вида `https://www.livelib.ru/reader/<username>/wish/print`.
2. [ ] Загружать HTML страницы.
3. [ ] Находить книги в списке.
4. [ ] Извлекать название, авторов и ссылку на книгу LiveLib.
5. [ ] Сохранять результат в JSON-файл.
6. [ ] Сообщать путь к файлу и количество найденных книг.

## Структура проекта

```text
livelib-wishlist/
├── SKILL.md
├── scripts/
│   └── livelib_wish_to_json.py
└── tests/
    ├── fixtures/
    │   └── wish_print_sample.html
    └── test_livelib_wish_to_json.py
```

## SKILL.md

В `SKILL.md` описать:

- когда использовать skill: если пользователь прислал ссылку на LiveLib wish-list print page;
- какой скрипт запускать;
- какой формат входа и выхода ожидается;
- какие ограничения соблюдать.

Пример workflow для агента:

1. Проверить, что ссылка похожа на `/reader/<username>/wish/print`.
2. Запустить скрипт `scripts/livelib_wish_to_json.py`.
3. Сохранить JSON в указанное место или в файл по умолчанию.
4. Вернуть пользователю количество книг и путь к результату.

## CLI-скрипт

Интерфейс:

```bash
python scripts/livelib_wish_to_json.py \
  "https://www.livelib.ru/reader/LiraLantan/wish/print" \
  --out wishlist.json
```

Рекомендуемые зависимости:

- `requests` или `httpx` для загрузки страницы;
- `beautifulsoup4` для парсинга HTML.

## Парсинг

Основная логика:

1. Найти ссылки на книги LiveLib.
2. Оставить ссылки, которые ведут на `/book/...`.
3. Взять текст ссылки как название книги.
4. Найти автора или авторов рядом с названием.
5. Преобразовать относительные ссылки в абсолютные URL `https://www.livelib.ru/...`.
6. Убрать дубли.
7. Сохранить список объектов в JSON.

## JSON-схема

```json
[
  {
    "title": "string",
    "authors": ["string"],
    "url": "string"
  }
]
```

Поле `authors` лучше хранить массивом, даже если автор один.

## Тесты

Покрыть сценарии:

1. Одна книга.
2. Несколько книг.
3. Несколько авторов у одной книги.
4. Относительная ссылка `/book/...`.
5. Дубли ссылок.
6. Пустая страница.
7. Изменившаяся верстка, при которой книги не найдены.

## Ограничения

Для аккуратного MVP:

- делать один запрос по ссылке, которую дал пользователь;
- не автоматизировать логин;
- не обходить капчи и защитные механизмы;
- не сканировать другие страницы LiveLib;
- не сохранять лишние данные, кроме названия, авторов и ссылки.

## Возможные следующие этапы

После MVP можно добавить:

- экспорт в Markdown или CSV;
- сравнение нового JSON со старым;
- отметку новых и удаленных книг;
- настройку имени выходного файла;
- обогащение данных через внешние книжные API.
