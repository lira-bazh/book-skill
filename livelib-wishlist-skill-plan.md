# План реализации skill для LiveLib wish-list

## Цель

Пользователь отправляет ссылку на обычную страницу списка книг LiveLib:

```text
https://www.livelib.ru/reader/LiraLantan/wish
```

Skill получает страницы wish-list с учетом пагинации, извлекает книги со всех
страниц и сохраняет список в JSON.

Минимальные поля для каждой книги:

```json
{
  "title": "Сто лет одиночества",
  "authors": ["Габриэль Гарсиа Маркес"],
  "url": "https://www.livelib.ru/book/..."
}
```

## MVP

Сделать один skill `livelib-wishlist`, который умеет:

1. [x] Принимать URL вида `https://www.livelib.ru/reader/<username>/wish`.
2. [x] Загружать HTML страницы.
3. [ ] Находить ссылки пагинации и загружать все страницы wish-list.
4. [ ] Находить книги в списке на каждой странице.
5. [ ] Извлекать название, авторов и ссылку на книгу LiveLib.
6. [ ] Сохранять результат в JSON-файл.
7. [ ] Сообщать путь к файлу, количество найденных книг и количество обработанных страниц.

## SKILL.md

В `SKILL.md` описать:

- когда использовать skill: если пользователь прислал ссылку на LiveLib wish-list page;
- какой скрипт запускать;
- какой формат входа и выхода ожидается;
- какие ограничения соблюдать.

Пример workflow для агента:

1. Проверить, что ссылка похожа на `/reader/<username>/wish`.
2. Запустить скрипт `scripts/livelib_wish_to_json.py`.
3. Скрипт должен обработать первую страницу и все страницы пагинации текущего wish-list.
4. Сохранить JSON в указанное место или в файл по умолчанию.
5. Вернуть пользователю количество книг, количество страниц и путь к результату.

## CLI-скрипт

Интерфейс:

```bash
python scripts/livelib_wish_to_json.py \
  "https://www.livelib.ru/reader/LiraLantan/wish" \
  --out wishlist.json
```

Рекомендуемые зависимости:

- `requests` или `httpx` для загрузки страницы;
- `beautifulsoup4` для парсинга HTML.

## Парсинг

Основная логика для каждой страницы:

1. Найти ссылки на книги LiveLib.
2. Оставить ссылки, которые ведут на `/book/...`.
3. Взять текст ссылки как название книги.
4. Найти автора или авторов рядом с названием.
5. Преобразовать относительные ссылки в абсолютные URL `https://www.livelib.ru/...`.
6. Убрать дубли.
7. Сохранить список объектов в JSON.

## Пагинация

Список книг на обычной странице wish-list может быть разбит на несколько
страниц. Скрипт должен собрать книги со всех страниц текущего списка.

Подход:

1. Начать с URL, который дал пользователь.
2. После загрузки страницы найти ссылки пагинации.
3. Оставить только ссылки того же пользователя и того же раздела `/reader/<username>/wish`.
4. Нормализовать относительные ссылки в абсолютные URL.
5. Обработать страницы без повторов.
6. Остановиться, когда новых ссылок пагинации больше нет.
7. Использовать лимит безопасности, например `--max-pages 50`.

Скрипт не должен переходить в другие разделы профиля, книги, рецензии,
подборки или страницы других пользователей. Разрешены только URL текущего
wish-list и его пагинации.

Если LiveLib не отдает страницы по сети, режим `--html` может обработать только
сохраненный HTML-файл одной страницы. Для полного списка в офлайн-режиме позже
нужно добавить поддержку нескольких HTML-файлов.

## JSON-схема

```json
[
  {
    "title": "string",
    "authors": ["string"],
    "url": "string"
  }
]
```

Поле `authors` лучше хранить массивом, даже если автор один.

## Тесты

Покрыть сценарии:

1. Одна книга.
2. Несколько книг.
3. Несколько авторов у одной книги.
4. Относительная ссылка `/book/...`.
5. Дубли ссылок.
6. Пагинация на две страницы.
7. Дубли страниц пагинации.
8. Ссылка пагинации в другой раздел игнорируется.
9. Лимит `--max-pages`.
10. Пустая страница.
11. Изменившаяся верстка, при которой книги не найдены.

## Ограничения

Для аккуратного MVP:

- делать запросы только к странице, которую дал пользователь, и к страницам пагинации этого же wish-list;
- не автоматизировать логин;
- не обходить капчи и защитные механизмы;
- если LiveLib возвращает `403 Forbidden` или перенаправляет на `/loginform`, использовать сохраненный HTML обычной страницы wish-list через `--html`;
- не сканировать другие разделы LiveLib;
- ограничивать количество страниц параметром `--max-pages`;
- не сохранять лишние данные, кроме названия, авторов и ссылки.

## Возможные следующие этапы

После MVP можно добавить:

- экспорт в Markdown или CSV;
- сравнение нового JSON со старым;
- отметку новых и удаленных книг;
- настройку имени выходного файла;
- поддержку нескольких сохраненных HTML-файлов для офлайн-сбора всех страниц;
- обогащение данных через внешние книжные API.
