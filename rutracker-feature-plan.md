# План доработки: поиск аудиокниг на RuTracker

## 1. Добавить модуль `rutracker-books.mjs`

- Создать модуль по аналогии с `livelib-wishlist/scripts/lib/litres-books.mjs`.
- Использовать существующий построитель поисковой строки `buildBookSearchQuery(book)`.
- Добавить `buildRutrackerSearchUrl(query)`.
- Формировать URL поиска как `https://rutracker.org/forum/tracker.php?nm=<encoded query>`.
- Хранить найденные ссылки в новом поле книги `rutracker_urls`.
- Сохранять существующие `rutracker_urls`, если они уже есть, и пропускать повторный поиск для таких книг.
- Новым книгам задавать `rutracker_urls: []`.

## 2. Добавить ожидание авторизации на RuTracker

- После поиска книг на Литресе открыть RuTracker в браузере.
- Использовать persistent browser profile, чтобы ручная авторизация сохранялась между запусками.
- Показать пользователю сообщение в CLI: RuTracker открыт в браузере, нужно авторизоваться вручную и нажать Enter в терминале.
- Не автоматизировать логин и пароль.
- После Enter продолжать workflow и запускать поиск по RuTracker.

## 3. Добавить браузерную обвязку

- В `livelib-wishlist/scripts/lib/browser.mjs` добавить получение страницы поиска RuTracker через Playwright.
- Добавить метод сессии `fetchRutrackerSearchPage`.
- Добавить открытие домашней страницы RuTracker или страницы форума перед ожиданием авторизации.
- Использовать общий browser session, который уже применяется для LiveLib, Яндекс Книг и Литреса.
- Возвращать HTML и фактический URL страницы поиска в том же стиле, что и существующие fetchers.

## 4. Реализовать парсинг результатов RuTracker

- Из HTML брать только ячейки таблицы с классом `.t-title-col`.
- Внутри каждой ячейки искать ссылку на тему.
- Нормализовать относительные ссылки до абсолютных ссылок `https://rutracker.org/forum/...`.
- Совпадение считать валидным, если нормализованный текст ячейки:
  - содержит все слова из нормализованной поисковой строки, которую отправляли;
  - содержит слово `MP3` без учета регистра.
- Дедуплицировать ссылки.
- Поддержать ограничение `maxResults`, как в поиске Литреса и Яндекс Книг.

## 5. Подключить RuTracker в основной workflow

- В `livelib-wishlist/scripts/livelib-wish-to-json.mjs` добавить обогащение RuTracker после обогащения Литресом.
- Запускать поиск RuTracker в том же сценарии, где уже используется браузерная сессия для текущего полного обогащения.
- После merge обновлять только поле `rutracker_urls`, не затирая остальные данные книги.
- Добавить CLI-счетчики:
  - сколько книг уже имели `rutracker_urls`;
  - сколько книг пропущено из-за существующих ссылок;
  - сколько книг получило новые ссылки.

## 6. Обновить JSON-merge и сохранение данных

- Убедиться, что merge сохраняет `rutracker_urls` из существующего JSON.
- Для новых книг добавлять пустой массив `rutracker_urls`.
- Не терять уже существующие дополнительные поля книги при повторном запуске.

## 7. Добавить тесты

- Добавить `livelib-wishlist/tests/rutracker-books.test.mjs`.
- Покрыть построение URL поиска.
- Покрыть ошибку для пустой поисковой строки.
- Покрыть извлечение ссылок только из `.t-title-col`.
- Покрыть обязательное наличие всех слов из поисковой строки в тексте результата.
- Покрыть обязательное наличие слова `MP3`.
- Покрыть дедупликацию ссылок.
- Покрыть сохранение существующих `rutracker_urls` и пропуск повторного поиска.
- Обновить CLI-тесты на порядок workflow: Литрес, затем ожидание авторизации RuTracker, затем поиск RuTracker.

Команда для проверки после реализации:

pnpm test
