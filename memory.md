# Project Memory

## LiveLib wishlist

- Wish-list открывается публично: отдельную проверку авторизации не делать.
  Если LiveLib уводит на защитную или неожиданную страницу, останавливать обработку.

- Книги LiveLib бывают не только `/book/...`, но и `/work/...`.
  Оба типа считаются валидными страницами книги; вложенные пути вроде `/readers` отбрасываются.

- Пагинация должна оставаться внутри `/reader/<username>/wish`.
  Разрешены обычный `?page=N` и `/listview/smalllist/~N`; футерные, mobile и tracking-ссылки игнорируются.

- Браузерный режим использует постоянный профиль `livelib-wishlist/.browser-profile`.
  Cookie и сессии не сохраняются отдельно от профиля.

## Yandex Books

- Поиск Яндекс Книг строится как `https://books.yandex.ru/search/all/<encoded text>`.
  Запрос собирается только из названия книги; совпадение результата проверяется по названию и автору.

- Валидные ссылки результата: только `/books/<id>` и `/audiobooks/<id>`.
  Не учитывать `/bookshelves/`, `/series/`, `/serial/`, `/authors/`, `/narrators/`, `/users/` и вложенные пути.

- Карточки выдачи Яндекс Книг читаются через `data-test-id="SNIPPET"`.
  Авторов брать из `data-test-id="SNIPPET_AUTHORS"`, а не из всех ссылок внутри карточки.

- Фильтр совпадений консервативный: название должно быть похоже, а если у исходной книги есть авторы, должен совпасть хотя бы один автор.
  Лучше пропустить сомнительный результат, чем записать неправильную ссылку.

- Результат обогащения хранится в `yandex_books_urls`.
  Поле всегда массив ссылок; пустой массив для ненайденных книг будет закреплен отдельным пунктом плана.

- При повторном запуске читать существующий выходной JSON и сопоставлять книги по LiveLib `url`.
  Если `yandex_books_urls` уже непустой, переносить его в новый результат и не искать книгу заново.

- В новом инкрементальном потоке сначала проверяется существование `--out`, до чтения LiveLib.
  Если файл есть, он читается сразу; merge развивается отдельными пунктами этапа 3.

- Существующий `--out` обязан быть JSON-массивом книг.
  Ошибка чтения, parse error или другая схема останавливают запуск до LiveLib/Yandex.

- Книги из LiveLib и существующего JSON сопоставляются только по нормализованному LiveLib `url`.
  `matchBooksByLiveLibUrl` также выделяет новые и удалённые книги для будущего merge.

- `mergeExistingLiveLibBooks` сохраняет объект из файла для книг, которые всё еще есть на LiveLib.
  Это нужно, чтобы не потерять `yandex_books_urls` и любые дополнительные поля.

- Новые книги из LiveLib в merge сразу получают `yandex_books_urls: []`.
  Так JSON-схема стабильна до запуска поиска на Яндекс Книгах.

- LiveLib wish-list считается источником актуального состава.
  Книги из существующего JSON, которых нет в текущем LiveLib списке, не попадают в merged результат.

- После merge порядок книг должен соответствовать текущему порядку LiveLib.
  Даже если существующий JSON был в другом порядке, актуальный список диктует порядок результата.

- Yandex enrichment в CLI запускается уже после merge.
  Книги с непустым `yandex_books_urls` пропускаются, а новые/пустые ищутся.

- После merge найденные ссылки Яндекс Книг обновляют только `yandex_books_urls`.
  `title`, `authors`, `url` и дополнительные поля из файла не перезаписываются.

- После LiveLib merge обновленный список всегда пишется обратно в тот же `--out`.
  Это верно и без `--with-yandex-books`: файл всё равно синхронизируется с LiveLib.

- При `--with-yandex-books` CLI печатает два счетчика: книги с непустыми `yandex_books_urls` и книги, пропущенные из-за уже существующих ссылок.
  Первый счетчик включает и свеженайденные, и переиспользованные ссылки.

- Задержка между сетевыми запросами фиксированная: 2000 мс для LiveLib пагинации и Yandex Books.
  CLI не должен принимать `--page-delay-ms` или `--yandex-delay-ms`.

- Навигация Playwright использует увеличенный timeout 120000 мс.
  Страницы Yandex Books могут долго не отдавать `domcontentloaded`, дефолтных 30 секунд мало.

- Временные ошибки навигации Playwright ретраятся 3 раза с паузой 2000 мс.
  Ретраить `ERR_NETWORK_CHANGED`, `ERR_TIMED_OUT`, `ERR_HTTP_RESPONSE_CODE_FAILURE` и timeout.

- Если поиск Yandex Books упал для одной книги, CLI пишет warning и продолжает.
  Для этой книги сохраняется `yandex_books_urls: []`, поэтому следующий запуск попробует снова.

- Инкрементальная статистика CLI также печатает: сколько книг было в `--out`, сколько найдено на LiveLib и сколько новых добавлено.
  При Yandex enrichment дополнительно печатается, сколько книг обогатилось новыми ссылками.

## Code patterns

- `scripts/livelib-wish-to-json.mjs` должен оставаться тонким CLI-оркестратором.
  Доменная логика живет в `scripts/lib/*.mjs`.

- Разделение модулей: `livelib.mjs` для LiveLib, `yandex-books.mjs` для поиска и матчеров, `browser.mjs` для Playwright, `json-output.mjs` для файлов.
  Общая нормализация текста и href лежит в `text-match.mjs`.

- Тесты не ходят в сеть и не открывают реальный браузер.
  Для браузерных сценариев использовать fake Playwright или подмененный fetcher.

- Тесты разделены по тем же границам, что и код: `livelib`, `yandex-books`, `browser`, `json-output`, `cli`.
  Новый тест лучше класть рядом с модулем поведения, а не в общий файл.

- JSON пишется через `writeBooksJson`, с созданием родительских директорий.
  Не перезаписывать LiveLib-поля при будущем обогащении существующего файла.
