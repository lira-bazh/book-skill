# Project Memory

## LiveLib wishlist

- Wish-list открывается публично: отдельную проверку авторизации не делать.
  Если LiveLib уводит на защитную или неожиданную страницу, останавливать обработку.

- Книги LiveLib бывают не только `/book/...`, но и `/work/...`.
  Оба типа считаются валидными страницами книги; вложенные пути вроде `/readers` отбрасываются.

- Пагинация должна оставаться внутри `/reader/<username>/wish`.
  Разрешены обычный `?page=N` и `/listview/smalllist/~N`; футерные, mobile и tracking-ссылки игнорируются.

- Браузерный режим использует постоянный профиль `livelib-wishlist/.browser-profile`.
  Cookie и сессии не сохраняются отдельно от профиля.

## Yandex Books

- Поиск Яндекс Книг строится как `https://books.yandex.ru/search/all/<encoded text>`.
  Запрос собирается из названия и уникальных авторов книги.

- Валидные ссылки результата: только `/books/<id>` и `/audiobooks/<id>`.
  Не учитывать `/bookshelves/`, `/series/`, `/serial/`, `/authors/`, `/narrators/`, `/users/` и вложенные пути.

- Карточки выдачи Яндекс Книг читаются через `data-test-id="SNIPPET"`.
  Авторов брать из `data-test-id="SNIPPET_AUTHORS"`, а не из всех ссылок внутри карточки.

- Фильтр совпадений консервативный: название должно быть похоже, а если у исходной книги есть авторы, должен совпасть хотя бы один автор.
  Лучше пропустить сомнительный результат, чем записать неправильную ссылку.

- Результат обогащения хранится в `yandex_books_urls`.
  Поле всегда массив ссылок; пустой массив для ненайденных книг будет закреплен отдельным пунктом плана.

## Code patterns

- `scripts/livelib-wish-to-json.mjs` должен оставаться тонким CLI-оркестратором.
  Доменная логика живет в `scripts/lib/*.mjs`.

- Разделение модулей: `livelib.mjs` для LiveLib, `yandex-books.mjs` для поиска и матчеров, `browser.mjs` для Playwright, `json-output.mjs` для файлов.
  Общая нормализация текста и href лежит в `text-match.mjs`.

- Тесты не ходят в сеть и не открывают реальный браузер.
  Для браузерных сценариев использовать fake Playwright или подмененный fetcher.

- Тесты разделены по тем же границам, что и код: `livelib`, `yandex-books`, `browser`, `json-output`, `cli`.
  Новый тест лучше класть рядом с модулем поведения, а не в общий файл.

- JSON пишется через `writeBooksJson`, с созданием родительских директорий.
  Не перезаписывать LiveLib-поля при будущем обогащении существующего файла.
